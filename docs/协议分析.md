# 协议分析笔记

> 所有结论来自对公开可获取的客户端程序与自身实验会话的观察，不含任何服务器端代码。
> 文中 `<ServerIP>`、`<账号>` 等均为占位符。

## 1. 客户端结构

```
WebLabClient.exe（实验大厅）
  ├─ 从 <ServerIP> 下载 <实验名>.lab 包
  ├─ 解包到 %TEMP%\lab\<编号>\
  ├─ 用加密参数启动 Main.exe（USTCORi.SimExp 引擎）
  └─ Main.exe 退出后 POST /ServiceAPI/UpdateRecord
```

`.lab` 包是自定义容器：每条记录 = 512 字节 UTF-16 文件名 + 若干长度字段 + 数据，内含
`Main.exe`、`SimExpConfig\`、`Resources\` 等。

启动参数是一段加密字符串，解密后是 `|` 分隔的 10 段 base64：

| # | 字段 | 示例 |
|---|---|---|
| 1 | hWnd | 窗口句柄 |
| 2 | tag | `-exam0` / `-exam1` / `-sim` / 其它 |
| 3 | paper | 试卷路径（空则用默认 `SimExpConfig\ExamConfig.bin`） |
| 4 | userid | `<账号>` |
| 5 | LabID | 实验编号 |
| 6 | LabName | `实验名.课程ID` |
| 7 | RecordID | 本次会话记录号 |
| 8 | md5Key | 会话校验串 |
| 9 | time | 开始时间 |
| 10 | ServerIP | `http://<ServerIP>:<端口>` |

## 2. 试卷文件 `ExamConfig.bin`

- 二进制，实为「gzip + 字表变换」后的 XML，变换口令硬编码在客户端：`haohaoxuexi,tiantianxiangshang.`
- 解密后是完整试卷：`ExamPaper/Title` + `ExamPaper/Content/Question/CheckPoint/{Status,TestTarget}`
- 每个判分参数结构：

```xml
<Para>
  <Name>List2_Time</Name>
  <VarType Count="10">TList</VarType>
  <StdResult>...</StdResult>     <!-- 标准值 -->
  <RealResult>...</RealResult>   <!-- 学生填写值 -->
  <JudgeRule><Rule>
    <StdValue>1</StdValue>
    <Range><Type>百分比</Type><Min>-0.05</Min><Max>0.05</Max></Range>
    <Score>1</Score>
  </Rule></JudgeRule>
</Para>
```

- 表格型参数的值是压缩表串：`(表头1,表头2);(行1列1,行1列2);(行2列1,...)`
- `StdSource=Exp` 表示标准值由仿真引擎运行时计算；模板里常见占位符 `NaN` / `0.000` / 空。

## 3. 提交接口

```
POST <ServerIP>/ServiceAPI/UpdateRecord
Content-Type: application/x-www-form-urlencoded

UserID=<账号>&LabID=<编号>&LabName=<实验名.课程ID>
&RecordID=<记录号>&FileName=<账号><yyyyMMddHHmmss>.xml
&Content=<base64(加密XML)>&Key=<签名>
```

签名（客户端 `Sec.GenerateKey`）：

```
text  = hex(MD5(serial))[4:8]                       // 8 位
text2 = (long.Parse(now.ToString(fmt)) + 常量).ToString()
text += hex(MD5(text + text2))[4:8]                 // 共 16 位
输出  = 交错拼接 text 与 text2，再做一次固定字符置换
```

其中 `serial = UserID + "," + LabID + FileName`，`FileName` 含**秒级时间戳**，
`fmt` 与置换表均在混淆代码里（未完全还原），因此**签名无法离线预生成**，
但**抓一次真实提交即可长期复用**（实测重放不校验时效）。

关键缺陷：**签名不覆盖 `Content`**。

## 4. 服务端返回码（实测）

| 返回 | 含义 |
|---|---|
| `1` | 成功 |
| `-3` | `RecordID` 不存在或与记录不匹配 |
| `-4` | `Key` / `FileName` / `UserID` 任一不匹配 |

（`Key` 传非 base64 会触发 WCF `FormatException`，说明服务端第一件事是 `Convert.FromBase64String`。）

## 5. 判分模型

- 逐参数比较 `RealResult` 与 `StdResult`，规则多为**相对偏差** `(Real-Std)/Std ∈ [-5%, +5%]`；
- 标准值有两种来源：模板中写死的真值，或引擎运行时计算（`StdSource=Exp`）；
- 模板里是 `NaN` / `0.000` 的参数，分母为 0 或 NaN，**任何值都判 0 分**；
- 部分参数（连线状态、退磁、档位、光强区间等）在 XML 里是 `double` 类型，存的是**状态码**，
  其含义由客户端私有映射决定，改文件填不出正确码，只能在界面里操作出来。

## 6. 客户端自带防护（观察）

- 大厅启动 `Main.exe` 后约 3 秒，会把磁盘上的 `Main.exe` 移到 `%TEMP%\TS_<ticks>.tmp`，
  然后把第 260–10240 字节写成随机数。运行中的进程不受影响，但**磁盘副本被破坏**，
  所以对 `Main.exe` 的静态补丁无效；
- 试卷与提交包共用一套固定口令，未做按会话派生密钥；
- 服务器的 WCF 异常会把堆栈与绝对路径返回给客户端（信息泄露）。

## 7. 未解决

- `Sec.GenerateKey` 中 `fmt` 的具体格式与置换表未还原（不影响使用，抓包复用即可）；
- 状态类参数的编码映射未知（可暴力枚举，代价高，不如直接操作界面）；
- 部分实验（如透镜成像）没有 `JudgeRule`，判分规则在服务端，需按内容反推。
